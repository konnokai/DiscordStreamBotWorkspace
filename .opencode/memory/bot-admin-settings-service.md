# Bot admin settings service

- Notifier implements `AdminSettingsService` under `SharedService/AdminSettings`.
- It builds the guild settings snapshot and executes admin commands, reusing existing Slash business services and DB tables, then invalidates notification caches.
- Snapshot source names fall back from local DB name to `YoutubeStreamService.GetChannelTitle` only when the local name equals the source ID.
- A Bot restart is required before the updated snapshot producer emits names using that fallback.
- Admin Redis request/reply uses channels `admin:settings:snapshot:request`, `admin:settings:command:request`, and `admin:settings:reply:{correlationId}`; reply timeout is 2.5s, matching the existing cluster query budget.
- Follow-up crawler/verification work extends the snapshot and command set with crawler and verification sections; it reuses existing platform services, role services, guild locks, DB primary keys, and Redis reconcile, with no new registry, interface, or schema. TwitCasting default crawler limit stays 2, matching Slash. Status as of 2026-11 transcripts: implemented and automated checks passed, but formal multi-shard/production acceptance remained unverified.
- Expanded snapshot now includes `crawlers` (youtube/twitch/twitcasting with enabled/count/limit/items) and `verification` (youtube/twitch arrays with source, role, previous role, deletionPending, probe mode/video, verified/pending counts; twitch includes tier role ids) plus `resources.roles` (id/name/position/managed/everyone/botCanManage).
- Domain entry points added on existing services: `YoutubeStreamService.AddCrawlerAsync/RemoveCrawlerAsync`, `TwitchService.AddCrawlerAsync/RemoveCrawlerAsync`, `TwitcastingService.AddCrawlerAsync/RemoveCrawlerAsync`, `YoutubeMemberService.ConfigureAsync/RemoveConfigurationAsync/SetProbeVideoAsync/UseAutomaticProbeAsync`, `TwitchSubscriptionService.ConfigureAsync/RemoveConfigurationAsync`. Slash handlers were reduced to Discord defer/confirm/localization shells and call these.
- `AdminSettingsService.ValidCrawlerOrVerificationPayload` validates crawler/verification mutation payloads; `CanManageRole` centralizes the bot-can-manage-role rule (ManageRoles, not everyone, not managed, below bot top role).
- Pure policy extracted as `SharedService/AdminSettings/CrawlerPolicy`: `ResolveLimit(configured, fallback)` treats 0/null as fallback; `HasGeneralEligibility(actor, owner, official, members, required)`; `CanRemove(ownerGuild, guild, botOwner)`. Twitch general eligibility threshold 200 with OAuth broadcaster bypass; TwitCasting 500; YouTube verification 250.
- Twitch verification upsert accepts a numeric canonical broadcaster ID directly instead of treating it as a login.
- Backend `TryReadSnapshotReply` now requires `Crawlers` and `Verification` non-null before accepting a snapshot. Frontend `AdminMutationReply` now preserves `code` so rejected mutations can show the specific reason instead of a generic message.
- Bot-owner DM notifications restored after the web-admin shared-service refactor: new `CrawlerOwnerNotifier` builds and sends the historical YouTube/Twitch/TwitCasting crawler-added embeds and owner management buttons; all three `AddCrawlerAsync` new-row success paths call it so Web and Slash share behavior. DM failures are logged and do not roll back successful mutations.
- `YouTubeMemberService.ConfigureAsync` restores the historical owner DM for first-time YouTube membership verification.
- `TwitchSubscriptionService.ConfigureAsync` now accepts `actorUserId` from both Web `AdminSettingsService` and Slash `TwitchSubscriptionSetting`, and sends a matching owner DM only when `TwitchSubscriptionRoleService` reports `IsSuccess && IsNew`; repairs/updates do not notify.
- Existing orphan crawler ownership transfers do not emit a new-crawler message because persisted trust/warning/recording states may not match new-row defaults.
- Added a focused crawler embed/button-route test. Verification on 2026-11-07: 618 tests passed, 36 environment component tests skipped; Release build 0 warnings/errors; `git diff --check` passed (line-ending warnings only). Uncommitted.
