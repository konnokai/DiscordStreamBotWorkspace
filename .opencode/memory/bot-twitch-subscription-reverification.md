# Bot Twitch subscription re-verification cycle

- `TwitchSubscriptionService.RunReverificationCycleAsync` runs as a single-flight hourly batch via `PeriodicRunner`: first run 1 minute after `Start()`, then every hour. `PeriodicRunner` never overlaps ticks; exceptions are logged and the next tick still runs.
- Each cycle order: (1) retry deletion-pending configs via `DeleteConfigurationAsync` (independent of `TwitchSubscriptionCheck` rows, so cleanup still retries after checks are gone); (2) select checks older than 1 hour whose config still exists, is not deletion-pending, and belongs to a shard owned by this process; (3) retry `PendingRoleRemoval` checks first under user lock then guild lock via `RetryPendingRoleRemovalAsync` (success deletes the check, failure bumps `LastCheckTime` for a 1-hour retry); (4) if Twitch API is disabled, skip only Helix queries/token refresh while the earlier deletion and role-removal work still ran.
- Twitch queries are merged by `DiscordUserId + BroadcasterId`, so one user subscribed to the same broadcaster across multiple guilds triggers a single `LookupAsync`; the result is applied per guild under the guild lock via `ApplyResultCoreAsync`.
- Authorization failure handling re-reads the DB before cleanup to avoid deleting a freshly re-linked authorization from a stale result; only confirmed `AuthorizationInvalid`/`AuthorizationMissing` clears that user's checks/roles on this shard.
- `ApplyResultCoreAsync` outcomes: `Subscribed` syncs shared + tier roles and updates tier/gift/`IsChecked`; `NotSubscribed` marks pending removal then removes roles (deletes check on success, otherwise retries next cycle); transient failures keep roles/state but bump `LastCheckTime`.
- Lock order is always user lock → guild lock, shared with manual verification/cancellation/authorization events.
- Rate limiting: `_rateLimitUntilByTwitchUserId` gates per Twitch user id; `TrackRateLimit` records the `Ratelimit-Reset` value from a 429, and `TwitchRateLimitPolicy.IsBlocked` skips that user until reset. Twitch Helix uses an 800-point token bucket per client id per user per minute; Discord role mutations compare the member's current `RoleIds` first and skip redundant `AddRoleAsync`/`RemoveRoleAsync`.
